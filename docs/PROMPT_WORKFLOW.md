# 使用一段完整 prompt 组织仿真

平台以当前项目为对象。电机只是示例数据，通用入口不切换成电机、不自动创建轴承模型，也不固定运行六项分析。

## 怎么使用

1. 启动 `Start.bat`，在工作台选择项目或导入 STEP。为需要施加载荷、约束或热边界的真实表面保存命名选区，例如“安装面”“受力端”“散热面”；装配体保留独立组件。
2. 直接使用主工作台右侧的 **仿真 Agent** 输入框；顶部 **指令仿真** 也会聚焦这里。长段自然语言选择 **Codex CLI**（使用已有登录）或 **Responses API**（使用已有 API 配置）。当前电脑已经完成 CLI 实测；另一台电脑需要先配好连接。
3. 粘贴下面的一整段 prompt，替换 `【】`。不需要的分析及条件整句删掉；项目中已有完整配置时可以直接写“继承已保存的某某工况”，只描述要改动的条件。
4. 点击 **发送并自动执行** 或按 **Ctrl + Enter**。条件完整后后台自动执行，页面保留模型树、中央视窗和右侧对话。展开“查看已解析的工况”可核对实际输入。缺项会集中显示；在输入框补充即可继续原指令，另起任务用右侧 **新对话**。只需检查配置时勾选 **仅草案**，随后可点击 **按此方案开始计算**。
5. 右侧显示解析、求解和导出进度；中央 **当前工况** 下拉框或左侧 **多物理场工况** 切换分析。使用场量和组件选择框查看云图，瞬态结果使用时间轴与 **播放**；静力和稳态显示“非瞬态过程”。右侧点击 **详细图文报告** 下载 PDF，或下载指标 CSV 和完整 ZIP（含文件清单）；中央各工况下方下载分项报告、MP4、HDF5 与快照。关闭网页不会取消后台任务，刷新会恢复当前项目的任务；过去的指令可从右侧 **历史** 打开。

解析阶段只产生类型化配置，主程序负责校验组件、选区、材料字段、单位约定与依赖，并调用真实求解器。语言模型不会生成求解代码或计算结果。

## 可复制的长 prompt

> 请针对当前项目中的 CAD 模型执行仿真，使用本项目已有的材料卡、组件、命名选区和连接配置，不导入其他示例。模型用途是【填写用途】，需要的分析为【静力、稳态热、瞬态热、高周疲劳、热结构耦合、周期接触及接触疲劳，按需保留】。材料使用【明确的已保存材料卡名称，或逐组件给出物性与来源】；在【真实命名选区】固定【X/Y/Z 方向】，在【真实命名选区】施加【方向、总力/压力/扭矩及单位】。热源设置为【组件总功率或表面热流】，散热设置为【选区、对流系数、环境温度，必要时发射率】，初始温度【℃】，无应力参考温度【℃】，瞬态时长【s】，时间步【s】，每【s】保存一帧。疲劳使用【载荷最小值、最大值及周期/时间历程】，目标【循环数】，采用【已保存的 S-N 或 Findley 数据及适用条件】。装配分析使用【明确的粘结或开闭接触对、摩擦、运动历史、机械约束、热连接、接触热导与间隙传热条件】；磨损使用【材料硬度、磨损系数及来源】，没有这些数据就不要推测寿命或磨损。各研究独立使用指定初始条件，只有我明确要求时才以前一研究结果续算。条件齐全后自动排队求解、检查结果，提供适用的应力、位移、温度、梯度、热流、疲劳危险位置、接触压力与间隙结果；用真实保存帧播放动态云图并导出 MP4、中文汇总与各工况 PDF、指标 CSV、原始 HDF5、工况快照及带哈希清单的 ZIP。静力与稳态标为非瞬态视角展示，累计寿命与损伤不画成裂纹生长。参数、来源、演示假设、未收敛项与未评估项写入报告。缺少关键条件或选区含义不明确时，一次列齐需要补充的内容，保留原指令供我补充。

不用为了填写 prompt 伪造数据。没有参数就说明“尚未提供”，平台会要求补齐；如果只想验证流程，可明确授权软件演示假设，但结果不能表述为实物验证。

## 项目已经配好时的简洁写法

> 只对当前项目执行分析。继承已保存的“静力基准”中的材料、支撑、连接与网格，将“端面力”改为沿 -Z 的 500 N；另建瞬态热工况，继承已保存的“升温工况”中的热源、散热与材料，初始温度设为 25 ℃，总时长 600 s、步长 10 s、保存间隔 30 s。两项独立执行，不加载任何其他示例，也不添加疲劳工况。条件完整后自动求解、生成真实温度帧动画和静力视角视频，导出中文报告、CSV、HDF5 与 ZIP；缺失条件先列出，不擅自补参数。

工况名称必须真实存在，平台会读取当前项目最近的最多 12 份不同研究配置，以及当前配置/项目示例配置。更早的历史可在指令中明确写出研究 ID，或用 API 的 base_case_ids 指定，也可复制为当前草案；用户可访问的项目历史使用分页，不受规划上下文条数限制。

## 结果与恢复

- 任务可以包含 1～12 个工况，按依赖排序；只失败一项时，独立工况继续，依赖项标为阻止执行。部分交付不会写成全部完成。
- 完全相同的研究在核对原始场、配置、网格与求解版本后可复用；改变条件会新建计算。“强制重新求解”不覆盖旧结果。
- 每个任务保存原指令、规划上下文、规划输出和求解快照。材料数据来源与求解结果分开记录。
- 服务重启会把未完成任务标为中断；手动点击“继续未完成任务 / 重试导出”。解析中断可重新提交原指令；已经取消的任务不会自动启动。
- 默认 CPU 六线程，单个服务最多一个重型求解。当前通用入口不安排 GPU 或未支持物理过程；用户明确要求时可设置 case.mesh.convergence=true 执行三档网格比较，或 time_step_validation=true 执行瞬态热/热结构步长减半比较（最多六次），验证只对应实际比较的工况和结果。旧结构工作台中的 GPU 功能仍可单独使用。
- 热结构是否为双向反馈取决于实际配置的开闭接触与界面热导；只有理想粘结的模型不能被报告成压力反馈接触。

## API 和 MCP

长指令请求：`POST /api/v1/projects/{项目编号}/analysis-plans`

```json
{
  "request_id": "客户端生成的唯一编号",
  "prompt": "上述完整自然语言指令",
  "provider": "cli",
  "execute": true,
  "force": false
}
```

此接口立即返回计划编号。`GET /api/v1/analysis-plans/{编号}` 查询解析状态；`needs_input` 时读取 `questions`，下一次请求增加 `previous_plan_id` 补充原指令；`submitted` 时读取 `run_id`。关闭 HTTP 客户端不终止解析或求解。

`GET /api/v1/analysis-runs/{run_id}` 查询研究及产物。`POST .../{run_id}/cancel` 取消；`POST .../{run_id}/resume` 恢复或重试导出；`GET .../{run_id}/files/bundle.zip` 下载。

本地不连接模型的客户端可读取：

- `GET /api/v1/projects/{项目编号}/analysis-context`：真实几何、材料与保存工况。
- `GET /api/v1/analysis-plans/schema`：计划结构。
- `GET /api/v1/studies/schema`：完整工况结构。

按 schema 生成计划后，将其 JSON 字符串作为 `prompt`，选择 `provider: "local"`。`case_json` 同样是 JSON 字符串；有 `base_case_id` 时递归覆盖所引用的保存工况，数组整体替换，未出现的字段保留。引用必须属于当前项目。离线还支持精确命令 `运行已保存研究 编号,编号`，不把任意自然语言近似解析成默认工况。

MCP 提供 `studio_analysis_context`、`studio_submit_analysis_plan`、`studio_analysis_plan`、`studio_analysis_run` 和 `studio_cancel_analysis_plan`，由当前会话直接组织配置并提交，不再嵌套调用另一个模型。

电机旧批次和示例文件保留。需要明确运行旧固定示例时才用 `POST /api/v1/analysis-runs` 并传 `template: "motor-bearing"`；普通的“运行全套分析”不会在通用入口隐式加载电机。
