# 组件材料与工况工作台 · 0.3

本文记录 0.3 引入的组件独立计算与验证。0.4 另提供受限的实验性[齿轮静态接触传力](GEAR_CONTACT.md)，不等同于通用装配接触。

## 界面使用

1. STEP 导入时实体编号留空，保留全部组件；STL 仍要求一个封闭连通实体。组件按照 CAD 实体编号命名，当前不恢复原 CAD 装配层级、零件名称或运动副。
2. 左侧组件树可以高亮组件，点击其材料名称可为该组件选择材料卡或填写自己的物性。材料库保存材料快照；内置钢材、铝材均为明确标记的教学假设值，不代表实际牌号。
3. 打开“工况设置”，在“组件材料”页为各组件选材料，在“载荷”和“约束”页选择组件及作用面。可按组件筛选条件，给一个组件添加多个力形成组合载荷。
4. “保存工况”不会运行计算；通过“打开已保存工况”切换配置。修改后再次保存会产生独立版本。历史配置和结果不随项目材料改动。
5. 多组件必须明确设置连接与计算方式。本文的“组件独立计算，互不传力”模式要求每个组件各自充分约束。“待定义连接”允许保存，禁用运行并在宿主校验中拒绝求解。0.4 的实验性齿轮模式有独立的轴孔与接触配置要求。
6. 顶部“双组件示例”创建一个独立演示项目，不覆盖当前项目。示例含两根不同材料的拉杆，分别固定左端、在右端施加 1000 N；配置可直接编辑。

## Agent 与数据

手动界面和 Agent 共用 LoadCase。`component_materials` 按 CAD 体编号保存材料；`selection.body_id` 定义表面载荷和约束的组件作用域；重力 `body_id=null` 表示所有组件，指定编号时仅作用于该组件。每个工况保存完整材料参数和边界条件，不依赖可变材料卡。

自然语言示例：

> 使用 GPU，按当前双组件工况继续，各组件独立计算、互不传力。保留各组件材料、固定约束和网格，只将组件 2 的 +X 总力改成 500 N，组件 1 保持 1000 N，自动计算并与上一版比较。

复杂组件指令使用 Codex CLI / Responses API。离线规则会明确要求改用组件界面或模型连接，不猜测组件编号与作用面。不能将需要接触、粘结或螺栓传力的组件解释为独立结构。

## 计算与范围

- 网格记录单元及表面的组件编号。独立计算会拆分 CAD 共享面的节点自由度，避免隐式粘结。
- GPU 按单元读取各组件的 Lamé 参数组装和恢复结果；CPU 用各组件独立 ELSET、MATERIAL 和 SOLID SECTION。改变任一组件弹性参数会使 GPU 矩阵分解缓存失效。
- 重力按所属组件密度积分；各不连通网格分别进行 6 个刚体运动的约束检查。
- 原始积分点强度按所属材料屈服值评估。任一组件缺屈服数据时，整体强度判定为未评估，已知组件仍保留独立结果。HDF5 / VTU 保留单元组件编号，PDF / CSV / 界面包含组件结果。
- 组件间粘结、通用接触分离、摩擦、螺栓连接整体求解仍是待实现能力。两个组件的独立结果不能说明装配整体强度；0.4 齿轮接触的范围见专门说明。
- 0.2 的性能报告属于当时的单材料实现，未将其加速比当成 0.3 多材料装配性能承诺。

## 验证

完整回归 40 项通过，随后组件专项 5 项通过（含新增共享 CAD 面独立自由度和 Agent 类型转换检查；合计覆盖 42 项不同测试）。最终日志见 COMPONENT_TEST_RESULTS.txt。

新增检查覆盖双材料 CPU/GPU 数值对照、相同载荷下弹性模量减半对应位移翻倍、组件屈服值、密度与重力作用域、组件材料改变后的缓存失效、缺失材料和连接拦截、逐组件欠约束、工况快照隔离。浏览器验证了组件材料选择、载荷作用域、工况保存重载、运行入口禁用，以及实际 GPU 结果和组件报告。PDF 已逐页渲染检查。

真实 Codex CLI 指令验证：组件 1 保持 1000 N，组件 2 从 1000 N 改为 500 N，自动完成 GPU 求解并比较。组件 1 应力/位移比为 1，组件 2 为 0.5；材料、支撑及网格保持不变。执行证据保存于 COMPONENT_AGENT_VALIDATION.json。

Agent 的组件材料输出使用严格类型列表，再转为宿主映射，避免动态键与 [OpenAI 严格结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)要求冲突；不降低参数校验或猜测材料。
