# ThermoForge Studio 0.8.0 升级说明

这是通用工作流、结果可信性和交付性能升级。电机只是回归样例；所有新指令使用当前项目的模型、选区和材料。已有原始场、工况快照、历史验证范围保留，不自动改写为新算法结果。

## 日常使用

1. 打开 `http://127.0.0.1:8877`，搜索项目；同名项目以短编号和更新时间区分。组件可以设置别名，内部编号保持不变。
2. 在研究设置中核对材料、载荷和热边界。草稿按项目、模型、分析类型自动保存；未补齐的配置保留草稿并显示错误，不进入求解。其他窗口修改时返回版本冲突，不能悄悄覆盖。
3. 在主界面输入完整要求。所有新指令共用计划接口。可以引用已保存工况，再指定改动；解析结果保存来源和参数差异。缺少数据时说明缺项，不套用其他示例。
4. 后台队列显示阶段、最近进展和可用资源。取消只影响本任务拥有的求解及导出；服务重启后需要显式恢复。已收敛热物理步保存到独立 HDF5 日志，未保存到最终输出时刻的物理步也保留。
5. 查看真实帧、固定色标、组件/接触局部和内部表面裁剪。剖视不插值内部截面场，界面会明确说明。温度、应力等危险位置根据保存数据定位；曲线区与时间轴同步。探针记录原始节点身份，对投影应力明确标为显示投影。
6. 完成后可仅生成报告、仅生成视频或重做全部导出。重新导出不执行求解；发布采用独立版本目录，旧版本保留。图文报告有目录，无附录，参数、依据与局限在正文中说明。

## 可信性规则

- 热和热结构续算采用同一个初始场加载器。来源必须完整、实际哈希一致，且节点、组件和选面网格身份完全匹配；报告记录真正读取的来源及其物理时间。
- 曲线每个节点按对应物理范围检查。对流、发射率、绝对温度、环境温度及温控上下限不能绕过校验。
- 手动、自然语言和 MCP 共用几何预检。不存在的体热源/载荷/疲劳组件及错误选区在网格前拒绝。
- 求解完成、力/能量平衡、网格敏感性、时间步验证、材料来源分别记录。缺少指标、文件损坏或证据过期均不能显示已验证。
- 只有启用热反馈的接触才构成双向热结构耦合。机械接触存在但热反馈关闭时，按单向热膨胀分析说明。
- 接触完全张开、无有效映射和数据缺失分别呈现。报告异常生成诊断和可用工况的部分交付，不能伪称全部完成。

## 接口增量

| 接口 | 用途 |
|---|---|
| `GET/PUT /api/v1/projects/{id}/analysis-draft?analysis_type=...` | 原始可编辑草稿；PUT 包含 `case`、`expected_revision`、`base_case_id`、`parameter_sources`。冲突返回409。 |
| `GET /api/v1/projects/{id}/analysis-comparison` | 原静力与新研究统一比较；返回可比性原因，几何/分析类型/时刻不同不直接相减。 |
| `GET /api/v1/projects/{id}/studies?limit=100&offset=0` | 先按项目筛选后分页；计划历史及批次列表同样支持分页。 |
| `GET /api/v1/analysis-runs?project_id=...` | 当前项目批次，不受其他项目数量挤占。 |
| `GET /api/v1/studies/{id}/result-index` | 哈希绑定的范围、真实时间轴、原始历程统计、危险位置及场说明。 |
| `GET /api/v1/studies/{id}/topology` | 几何只读取一次；`node_ids` 为原始1起始节点编号。 |
| `GET /api/v1/studies/{id}/frames/{index}/values?fields=temperature` | 仅请求需要的场值与位移；旧完整帧接口继续可用。 |
| `GET/POST /api/v1/studies/{id}/probes` | 保存探针，POST 的 `node_index` 为0起始原始节点下标。 |
| `GET /api/v1/studies/{id}/probes/{probe_id}` | 实际探针历程、单位、原始哈希及数据位置说明。 |
| `GET /api/v1/studies/{id}/checkpoints` | 已提交物理步与独立 HDF5 下载位置。 |
| `POST /api/v1/analysis-runs/{id}/exports` | `{request_id,scope:"report"|"video"|"all"}`；仅导出，幂等提交。 |
| `GET /api/v1/analysis-runs/{id}/exports` | 导出历史；批次详情的 `latest_export` 显示最新任务。 |
| `POST /api/v1/analysis-runs/{id}/exports/{export_id}/cancel` | 取消独立导出，保留上一版产物。 |
| `GET /api/v1/analysis-runs/{id}/exports/{export_id}/log` | 查看本次导出诊断日志。 |
| `GET /api/v1/projects/{id}/thumbnail` | 实际 CAD 缩略图，绑定来源及几何哈希。 |
| `PATCH /api/v1/projects/{id}/component-aliases` | 保存 `{aliases:{组件编号:名称}}`，绑定当前模型。 |
| `GET /api/v1/execution/queue` | 活动作业与资源；排队位置是当前顺序，不编造完成时间。 |
| `GET /api/v1/storage/inventory` | 文件分类与占用预览；没有自动删除行为。 |

通用计划的单项研究可使用 `time_step_validation:true`、`max_time_step_halvings:6`。仅瞬态热和瞬态热结构适用；三档网格使用 `case.mesh.convergence:true`。比较必须使用相同物理配置和网格，保存时刻匹配，且各自平衡检查通过。

## 存储与恢复

资源预检计入保存帧、收敛步日志、最大界面迭代和减步试算的重启动文件。估算不是实测峰值；持续磁盘检查保留至少256 MiB，空间不足时停止后续工作并保留已提交阶段。程序不降低载荷、不自动粗化网格。由于估算更完整，过去能够提交但中途撑满磁盘的工况，现在可能提前被拒绝。

文件分为原件与证据、恢复必需、可再生成产物和待审阅诊断四类。自动删除始终关闭。已有历史目录先生成清单，任何空间整理应单独明确选择范围。中断日志可供检查；重新计算仍需核对原生求解输入，日志本身不保证任意位置安全重启。

## 发布和验证边界

`BUILD-MANIFEST.json` 记录 Python、科学计算依赖、CalculiX、后端及前端源文件和构建产物哈希。发布 ZIP 另有逐文件清单。重新构建前端后执行 `python scripts/build_manifest.py`；打包器拒绝与记录不一致的源文件、运行环境或构建产物，包括新增和缺失文件。PDF 分别显示平台版本、报告格式版本及原工况套件版本。

本版本在 Windows x64 / Python 3.14 上做 CPU 回归。既有 GPU 能力保留，本轮未宣称 GPU 重新验收。解析题、小型实际求解和浏览器检查证明各自测试范围，不能替代用户材料标定及实际产品局部网格收敛。性能验收记录后端函数与 HTTP 测量，二者分开报告。
