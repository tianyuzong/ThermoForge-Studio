<h1><img src="static/thermal-studio-logo.png" height="40" alt="Thermal Studio logo" style="vertical-align: middle;"> ThermoForge</h1>

**ThermoForge 是一个由 Agent 辅助配置与规划的本地三维热仿真及热结构分析平台，面向实物加工、打样前的热设计评估。** 导入 STL / STEP 数字模型后，可以预测温度分布、热变形与热应力，提前识别局部过热、温度不均和安装面翘曲等问题，为结构、材料及散热方案的调整提供计算依据。

本地应用与 Codex 插件以 **Thermal Studio** 名称提供。

通过自然语言描述工业场景、工作条件和设计目标，Agent 会拆分工况、补充必要信息，并生成可检查、经宿主校验的配置。用户整体确认后，平台按依赖关系执行计算、继承完整温度场、复用通过校核的已有结果，并汇总分析报告。例如，功率模块散热安装座可以依次评估正常风冷、停风后的温升，以及独立的高低温环境循环。

平台支持金属、高分子、玻璃与陶瓷材料预设，提供温度、位移和应力云图、接触面翘曲与设计限值检查，以及基于实际保存温度场的热扩散动画和 MP4 导出。中文 PDF 综合报告、指标 CSV 和配置及结果包记录分析条件、计算结果、校核依据与未完成项目，便于设计评审和后续样机验证。

在 CAD 设计阶段比较方案，有助于减少样机迭代，为缩短研发周期、降低打样成本和改善高低温工况下的产品设计提供支持。当前热结构分析采用小变形线弹性模型；实际成本收益与产品可靠性仍需结合项目记录、真实装配条件和试验验证。具体适用范围见下方“物理模型与已知限制”。

系统在本机运行，包含 Python 仿真服务、浏览器操作界面和 Codex 插件源码。核心计算采用 Gmsh 四面体网格、scikit-fem 有限元组装及 SciPy / CuPy 求解，支持 CPU / CUDA 设备选择和受资源限制的多工况并行执行。

## 快速开始（Windows）

准备 Python 3.11 或更新版本，以及支持 WebGL 的浏览器。使用 Git 获取源码后，在 **仓库根目录**运行以下命令：

```powershell
git clone https://github.com/tianyuzong/ThermoForge.git
cd ThermoForge
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1 -Device auto
```

`Install.ps1` 创建 `.venv` 并安装 [requirements.txt](requirements.txt) 中的依赖；首次安装需要联网，依赖中包含 CUDA 相关包。`-Device auto` 在 GPU 不可用时回退到 CPU，CPU 运行不要求有 NVIDIA 显卡。

启动后打开 [本地仿真界面](http://127.0.0.1:8765/)。服务只监听本机，Three.js 等页面依赖已保存在 `static/vendor/`，常规本地仿真不依赖 CDN 或 Codex。

### 启动、停止与计算设备

```powershell
# 强制使用 CPU
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1 -Device cpu

# 要求可用的 NVIDIA CUDA 环境，检测失败时直接报错
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1 -Device cuda

# 更换端口，并禁止自动打开浏览器
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1 -Device auto -Port 8766 -NoBrowser

# 查看默认端口服务的实际计算设备与状态
Invoke-RestMethod http://127.0.0.1:8765/api/health

# 停止服务及正在进行的计算；自定义端口时传入对应 -Port
powershell -NoProfile -ExecutionPolicy Bypass -File .\Stop.ps1 -Port 8765
```

| 启动入口 | 默认设备行为 |
| --- | --- |
| `Start.bat` 或未传 `-Device` 的根目录 `Start.ps1` | `cuda`，CUDA 不可用时启动失败 |
| `plugins/thermal-studio/scripts/start.ps1` | `auto`，CUDA 不可用时回退 CPU |
| 直接运行 Python 服务 | 读取 `THERMAL_DEVICE`；未设置时为 `auto` |

启动脚本会用 `-Device` 的值覆盖 `THERMAL_DEVICE`，因此通过脚本切换设备时应明确传参。CUDA 用于温度场的稀疏线性求解；模型处理、网格生成、有限元组装、热弹性和导出仍在 CPU 上执行。`auto` 对瞬态采用可复用矩阵分解的 CPU 求解，对稳态在 CUDA 可用时使用 CUDA；显式 `cuda` 可让瞬态也使用 GPU。GPU 显存占用不是求解效率指标，应以相同网格和输出下的实测耗时及残差为依据。

多工况执行采用依赖调度：前置完整温度场通过结果校核后，配置 Agent 才绑定实际结果 ID；独立工况可以同时执行。默认在至少 48 GiB 内存、8 个逻辑 CPU 的机器上开放两个求解槽位，其他机器一个；第二个算例还要求提交时至少 16 GiB 可用内存。这是保守的准入门槛，不是精确内存峰值预测。取消工作流会停止其全部运行算例，保留已完成结果。`/api/health` 的 `execution` 返回并发上限、内存与瞬态设备选择；各算例审计记录实际温度求解设备。

瞬态结果的播放、暂停、时间轴拖动以及温度/位移/应力切换使用实际保存帧；非均匀保存间隔显示真实时间及帧间时间差。播放帧率只控制观看速度。稳态显示末帧平衡结果并禁用时间动画。

### 热扩散动画与视频导出

页面顶部、**智能助手**左侧的 **运行记录** 按钮可展开历史记录。列表支持滚动，点击已完成的记录打开结果；点击空白处或按 Esc 收起列表。

在已完成的瞬态算例结果页点击 **热扩散动画**，打开双视角动画：左侧显示实际温度，右侧显示相对当帧工件最低温的温差；两侧色标全程固定，下方曲线与时间轴同步。可以旋转、缩放、暂停或拖动时间轴，关闭后返回原结果页。稳态算例禁用此入口。

窗口顶部提供 **下载交互动画** 和 **导出 MP4**。HTML 包含原始有限元外表面的节点温度和本地 Three.js，可独立打开。MP4 按默认双视角导出，将仿真过程压缩到 15 秒，再停留末帧 2 秒；非均匀保存间隔按真实时间比例保留，24 fps 编码只重复保存帧，不生成额外物理结果。当前 MP4 导出支持最多 600 帧，交互预览保留完整帧数据。

导出在独立后台进程执行，同一时间只生成一个视频；界面显示绘制和编码进度。动画与视频缓存在原算例的 `thermal-animation/` 子目录，结果或渲染版本改变后自动失效。此过程不修改仿真配置，也不重新求解。

视频导出依赖 `requirements.txt` 中的 Playwright 与 imageio-ffmpeg。Windows 默认使用已安装的 Microsoft Edge；其他环境可设置 `THERMAL_VIDEO_BROWSER=chromium`，并在应用 Python 环境运行 `python -m playwright install chromium`。交互动画预览不依赖后台视频浏览器。

关闭网页不会停止服务。修改设备或环境变量后，需要先停止已有服务，再从设置了新变量的终端启动。日志位于 `.runtime/server.log` 和 `.runtime/server-error.log`。

## 第一个三维算例

1. **导入模型。** 上传封闭的 STL 或 STEP / STP。STL 需指定坐标单位，STEP 按文件声明单位解释；额外尺寸倍率会改变最终大小。导入后先检查实际尺寸。
2. **设置材料。** 选择基础材料；如需多材料，可添加方框区域。预设物性是示例值，应按材料牌号和温度调整。
3. **添加热源。** 面热源必须刷选或按朝向选取受热面；点热源必须有有效位置。填写总功率及开始、结束时间，仅设置材料和计算时长不会产生热源。
4. **设置散热。** 配置环境温度与换热系数 `h`，或创建指定散热区。`h=0` 表示不施加该项对流；热源面是否使用默认散热由相应选项控制。
5. **配置计算。** 设置初始温度、时长、时间步长、保存间隔和网格尺寸，运行仿真。
6. **检查结果。** 查看温度动画、剖面、材料体积、热源映射和能量检查，再按需要导出或保存算例。

界面字段以各自显示的单位为准；API 中带 `_m` 的坐标、半径和网格尺寸使用米，功率使用 W，时间使用 s，温度使用 °C。仓库不包含本机 `data/` 中的模型，示例模型的尺寸与质量取决于实际导入设置。

本地页面入口：[三维仿真](http://127.0.0.1:8765/) · [CPU 热仿真](http://127.0.0.1:8765/cpu.html) · [界面使用说明](http://127.0.0.1:8765/guide.html)。以上链接需要服务已启动；使用其他端口时相应修改地址。

### Demo 1：智能助手——正常风冷稳态分析

打开 **智能助手 → Codex**，复制下面整段，点击 **生成配置**。核对材料、选区和参数，回答尚缺的信息后，点击 **确认并仿真**。

```text
请为当前已导入的 power_module_heatsink.step 建立一个独立算例，
名称为“散热安装座：正常风冷6 mm稳态基准”。

【模型与配置起点】
工件应为180 × 120 × 44 mm，包围盒为
X=[-90,90]、Y=[-60,60]、Z=[-4,40] mm。
```

## 仿真助手

先加载一个模型，再打开“智能助手”。生成配置只创建草案；选择“应用后修改”可回到主界面检查参数和选区，选择“确认并仿真”才会提交计算。

### 连续对话与确认流程

1. 输入初始目标，点击“生成配置”。复杂描述、指代和简短选择使用 **Codex** 模式。
2. 助手提出问题后，在“继续补充或回答问题”中回复，点击“发送补充”，或按 `Ctrl / ⌘ + Enter`。可以分次回答，无需重写全部要求。
3. 每轮结合前文重新核对材料、边界、热源、时间、网格等参数。未解决的必需问题继续追问；已明确的参数沿用，后续改口只更新对应设置。
4. 全部待解决问题处理完且配置与几何校验通过后，“应用后修改”和“确认并仿真”才可用。后者由用户点击后提交计算；输入新的补充会再次禁用这两个按钮，需先发送并重新校验。

| 当前状态 | 助手行为与下一步 |
| --- | --- |
| 缺少必需参数、热源位置无效、描述冲突或要求无法表达 | 显示待解决问题，保留前文，继续补充；不能确认仿真 |
| 一次只回答了部分问题 | 保留已答复内容，继续追问剩余项 |
| 所有问题解决且校验通过 | 显示参数变化，允许继续修改或确认运行 |
| 网络、CLI 启动或请求超时 | 保留本条输入供重试；失败请求不会重复计入对话 |

例如，助手问“中心不在实体内，是否外置？需要观察多久的冷却过程？”后，可先回复“同意改用外置热源”，再回复“仿真总时长 300 秒，热源仍在 180 秒关闭”。助手提出的可选方案不会自动视为用户同意。希望观察停止加热后的变化时，需要将仿真总时长设得晚于热源关闭时间；只观察加热过程则不必额外延长。

每轮保留用户要求、助手追问及最近一次通过校验的草案；已完成的新增或删除操作不会在后续轮次重新执行。本地规则适合“环境温度 30°C，网格尺寸 3 mm”等明确修改；无法判断简短回复或复杂上下文时会提示切换 Codex，并保留对话。主界面里尚未选面的热源、无效步长等未完成参数也可以通过对话继续修正，通过校验前不允许确认运行。

“新对话”以主界面当前参数重新开始。关闭助手窗口会保留本页记录；切换模型、加载算例或修改主界面参数后会重新建立配置基准，刷新页面会清空对话。请求失败时保留输入供重试，不会重复记录同一条消息。对话内容与配置在 Codex 模式下一同交给所选服务处理；聊天本身不会提交仿真。

### 解析模式与连接方式

| 页面模式 / 配置 | 行为 |
| --- | --- |
| 本地规则解析器 | 无需联网，按内置规则识别参数；复杂请求需检查实际生成内容 |
| Codex，`THERMAL_CODEX_PROVIDER=cli`（默认） | 本地规则生成候选，Codex 通过 `thermal-config` skill 核对并返回修正；沿用 CLI 已有登录态，找不到 CLI 时明确报错 |
| Codex，`THERMAL_CODEX_PROVIDER=api` | 使用 OpenAI Responses API，需要 `OPENAI_API_KEY` |
| Codex，`THERMAL_CODEX_PROVIDER=auto` | 优先 CLI，仅在找不到 CLI 时改用 API；CLI 请求失败不会自动切换 API |

CLI 模式需要安装并登录官方 Codex CLI，可在终端通过 `codex --version` 和 `codex login status` 检查。程序也会搜索 Windows 上官方 CLI 的本地安装目录，可用 `THERMAL_CODEX_COMMAND` 指定可执行文件路径。调用使用临时会话和只读沙箱。

CLI 配置生成复用 [thermal-config skill](.agents/skills/thermal-config/SKILL.md)：规则层负责单位、材料、热源和几何选区；Codex 对照原始指令检查候选，只返回需要更正的参数路径和值。后端使用 `--output-schema` 约束修正格式，并对合并结果再次执行配置与几何校验。该模式仍会真实调用 Codex，不会将规则结果直接冒充模型结果。网页的 API 模式也使用同一套对话核对与追问协议；旧的单次 Python API 调用保留完整配置生成方式。

网页核对阶段的 CLI 子进程会关闭 shell、浏览器、应用连接等额外工具，减少重复读文件和调用脚本的等待；这些设置仅用于本次子进程，不修改用户的 Codex 配置或独立技能的工具能力。

草案显示“配置 Skill”和本次生成耗时，并列出散热、辐射、空气间隙、网格等参数变化。规则候选没有覆盖的复杂描述由 Codex 修正；无法确认选区或参数时会提出问题。

配置助手按当前 `Simulation` 定义向 Codex 提供完整字段合约，包括当前值为空的相变、温控、材料区域和功率曲线。字段类型、范围和必需值从实际 Schema 生成，字段说明与草案变更摘要共用同一份映射。新增字段漏配说明时，测试会报错。

| 参数类别 | 当前三维配置可表达的内容 |
|---|---|
| 材料 | 基础材料、组件覆盖、矩形材料区域；导热系数、密度、比热容、线膨胀系数；起熔温度、相变温区宽度和潜热 |

| 求解与输出 | 瞬态/稳态、总时长、时间步长、结果保存间隔、网格尺寸、算例名称 |

本地规则支持上述常见标量、单位、组件物性、局部边界和明确格式的控制参数；材料区域与复杂自然语言定义使用 Codex 核对。局部和全局参数分开处理，未提及的设置保留，后续明确改口覆盖对应字段。草案会显示相变、线膨胀、半径、温控、局部发射率及清除操作等细节。`K/W` 与 `m²·K/W` 等不能直接互换的单位会要求补充信息。

识别范围由当前三维求解器的字段决定：固定温度边界、CFD 流场、各向异性或一般温度相关物性、表面间辐射视角因子尚不能在该配置中表达；不会用高对流系数、空气间隙导热等条件替代。CPU、水冷网络、制冷循环和反算的独立工作台参数不混入三维模型。配置识别测试不等于对应物理模型已完成工程验证。

使用 Codex 时，自然语言目标、当前配置和模型几何摘要会交给所选服务处理；三维仿真计算仍在本机执行。Codex 连接失败会显示错误，不会静默切换到本地规则解析器。

### 包含热源的指令示例

在已经导入模型的页面选择 **Codex**，输入：

```text
基于当前已加载模型创建一个瞬态导热算例，保留当前网格尺寸。
基础材料使用铜，初始温度 25°C，环境温度 25°C。
热源列表仅保留一个名为“顶部加热”的面热源：总功率 20 W，
从 0 秒持续到 600 秒，选择模型顶部（+Z）的外表面作为受热面。
全部外表面设置对流散热，换热系数 10 W/(m²·K)，包括热源面。
仿真总时长 600 秒，时间步长 5 秒，每 5 秒保存一帧。
不使用功率曲线、温控、辐射、相变或额外接触热阻。
如果顶部没有可用受热面，请提示我重新选择，不要生成没有热源的配置。
```

草案应包含 **20 W 热源、0–600 s 启停时间和非零受热面数**。确认前通过“应用后修改”检查选区，尤其要核对模型摆放方向和尺寸。

“顶部/底部、左/右、前/后、全部外表面”会由本地几何代码转换为真实面编号。两种解析器共享组件与坐标选区，例如“组件 2 外表面”“组件 2 顶部”“x=10 mm 附近表面”；点热源的坐标单独处理。缺少可定位的组件几何时会要求手动选面。轴向选区取该方向最外侧 3% 范围内、法向朝向该方向的外表面三角面，它不代表任意形状完整的上半部分。缺少热源、选区为空、面编号无效或模型不匹配时，草案不能确认运行。

热源描述会先区分新增、修改与删除，再将后续功率、位置、半径和启停时间归到对应热源。“单独加一个/另外添加/再加一个”会保留已有热源；已有热源可用序号或带引号的名称定位。只改位置、半径或时间时不必重复功率；新热源缺少功率时会明确询问。多热源的跨句描述和后续改口分别处理，较复杂的归属仍由 Codex 对照原文核对。

例如：“另外加一个 15 W 点热源，放在模型内部中心，半径 2 mm，从 20 秒到 90 秒；把第二个热源的结束时间改为 150 秒，其他设置不变。”已有点热源也可描述为“把第二个热源往左挪 5 mm”，或仅改某个轴的坐标，保留其他坐标。模型或组件“中间/中心”按对应包围盒中点定位，草案会提示核对；封闭几何中位于空腔或实体外的嵌入点会被拦截，不能自动移到附近墙面。未封闭几何无法据此验证实体内外。表面中央的局部加热需要明确范围或刷选，不能扩大为整个面。

### 新建热源与确定位置

| 想表达的操作 | 建议描述 |
| --- | --- |
| 当前没有热源 | `新建名为“中心热源”的点热源，功率 300 W，作用半径 15 mm……`；不能仅要求修改一个不存在的热源或保留不存在的半径 |
| 在已有配置上再加一个 | “另外添加一个……”；同时给出新热源的功率与位置，点热源可明确指定作用半径 |
| 修改现有热源 | 指定名称或序号，例如 `把“中心热源”功率改为 300 W，其他参数不变` |
| 放在模型内部中心 | 使用整个模型包围盒中点，先检查该点是否在实体内；`center_in_solid=false` 仅表示不在实体内部，不能据此区分空腔与实体外 |
| 放在表面中央 | 明确哪一个表面，或先刷选，再确定表面上的实际点坐标；表面点热源仍是局部加热，与整个面的面热源不同 |
| 放在地面 | 明确指的是地板上表面，并确认位置或选区；轴向“底部”对应最外侧向下的面，未必是室内可见地面 |

如果中心检查失败，确实希望保留中心坐标并改为外置时，可回复：

```text
同意保留刚才的中心坐标，将这个热源改为外置点热源。
功率、作用半径和启停时间沿用前文已经明确的数值，其他参数不变。
如仍有必需问题，请继续询问，全部通过后生成待确认配置。
```

表面或外置点热源会将功率按位置与作用半径分配到工件边界节点；嵌入热源使用体网格节点。这是固体中的热负荷施加方式，外置选项没有引入独立的空气流动或热源到工件的辐射传播模型。草案中点热源的 `faces` 可以为空，应核对其三维坐标、放置方式和半径；面热源则需要非空的受热面选区。

### 较强热源与长时间热扩散示例

先在“热源”中创建一个名为“地面热源”的热源，并完成位置设置：点热源填写已核对的地板上表面坐标及作用半径；面热源刷选地面局部区域。然后在助手中输入以下修改要求，保留已设置的位置：

```text
将已有的“地面热源”恒定总功率提高到10000 W，保留热源类型、
放置方式、位置、选区和作用半径。第0秒开启，第14400秒关闭，
不使用功率曲线或温控。其他热源保持不变。

采用瞬态仿真，总时长21600秒，即6小时；
计算步长10秒，每120秒保存一次结果。
前4小时加热，后2小时观察停止加热后的温度变化。
材料、网格和散热条件保持不变。

请核对完整参数，必需问题未解决时继续询问，
通过后生成供我点击“确认并仿真”的草案。
```

上述数值是扩散观察示例，温升和传播范围取决于工件尺寸、材料、选区与边界条件。户型几何不会自动变成建筑材料；如果当前材料是铜，得到的是该材料的固体导热结果。仿真时长指模型中的物理时间，实际计算耗时取决于网格、步数和计算设备。

当前单次配置要求 `duration_s / dt_s ≤ 5000`、`duration_s / save_s ≤ 300`。上例对应 2160 个时间步、181 个保存时刻（包含初始时刻），符合这两项限制。延长总时长时应同时检查步长与保存间隔；助手不会为了通过资源校验而自动放宽用户明确指定的数值。

在启动服务前设置；服务已运行时，设置后需重启才能生效。

| 变量 | 用途与默认值 |
| --- | --- |
| `THERMAL_CODEX_PROVIDER` | `cli` / `api` / `auto`，默认 `cli` |
| `THERMAL_CODEX_COMMAND` | 可选的 Codex CLI 可执行文件路径 |
| `THERMAL_CODEX_MODEL` | 可选的 CLI 模型；不设置时沿用 CLI 配置 |

| `OPENAI_BASE_URL` | API 服务根地址，默认 `https://api.openai.com/v1` |
| `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` | 显式代理设置，CLI 子进程优先沿用 |
| `THERMAL_DEVICE` | 直接启动 Python 时的 `auto` / `cpu` / `cuda`；启动脚本会覆盖此值 |
| `THERMAL_CUDA_DEVICE` | CUDA 设备编号，默认 `0` |
| `THERMAL_MAX_PARALLEL_JOBS` | 求解进程上限 `1` 或 `2`；默认按 CPU、总内存决定，额外算例还需通过可用内存检查 |
| `THERMAL_CPU_THREADS` | 每个求解进程内部的 BLAS/OpenMP 线程数，默认 `1`，避免多个工况各自占满 CPU；不改变仿真参数 |

```powershell
$env:THERMAL_CODEX_PROVIDER = 'cli'

powershell -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1 -Device cpu
```

未显式配置代理变量时，CLI 子进程在 Windows 上读取已启用的系统手动代理，并将本机地址加入直连范围；不会修改系统或其他进程的代理。仅配置 PAC 脚本的环境需要另行提供可用的代理环境变量。页面显示等待时长，并区分启动失败、超时和配置校验失败。

## 物理模型与已知限制

三维瞬态求解采用 P1 四面体有限元、一致质量矩阵和后向欧拉时间积分。对流边界输入的是给定换热系数，程序不求解实际风速、流场或流体压力。STEP 方框材料区域参与 CAD 分割；STL 方框区域按单元中心分配，边界精度受网格影响。

以下限制在当前实现中仍需注意：

| 功能 | 当前限制 |
| --- | --- |
| STEP 多个独立实体 | 组件编号映射存在已知问题，可能将多个实体归入同一组件，影响按组件赋材与空气间隙传热；不能仅凭界面材料设置判断分配正确 |
| 功率曲线与相变 | 功率曲线折点尚未自动加入时间网格；跨越折点可能产生输入能量误差。相变按上一时刻温度更新等效热容，跨越相变温区可能触发能量检查失败 |
| 接触热阻与空气间隙 | 接触热阻以材料导热率修正近似，具有网格依赖；空气间隙使用简化几何配对与 `k·A/间距`，未完整处理遮挡、朝向和流动 |
| 热膨胀位移与热应力 | `structural` 开启时采用三维小变形线弹性有限元，支持自由体或固定面及方向；未开启时保留原有自由膨胀估算，不能视为结构求解。暂不支持塑性、蠕变、疲劳寿命、机械接触和大变形 |
| 稳态结果审计 | 稳态报告部分能量字段仍沿用瞬态命名，单位与收敛判定有待完善，不能将其直接作为瞬态能量审计使用 |
| CPU 风冷 / 水冷工作台 | 属于集中参数热网络；当前水流量单位换算和显式时间积分稳定性存在已知问题，大步长可能产生异常温度，定量结果需修正与复核 |
| 换热反推与循环估算 | 基于集中参数或理想温差模型；未接入完整工质物性和设备性能曲线 |

开始验证时可使用单一材料、恒定功率和对流边界。程序尚未自动完成网格 / 时间步长收敛分析；应比较不同离散设置，并核对实际尺寸、材料体积、总输入功率和关键温度。能量残差较小本身不能证明物理模型与局部温度正确。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 双击 `Start.bat` 提示 CUDA / CuPy / DLL 不可用 | 在仓库根目录改用 `Start.ps1 -Device auto` 或 `-Device cpu`；如需 GPU，再检查对应 CUDA 环境 |
| 网格生成后出现 `failed to open nvrtc-builtins64_126.dll` | 求解器会按 CuPy 实际加载的 NVRTC 路径加载同版本 builtins，并在网格生成前执行真实编译和稀疏求解自检。`/api/health` 的 `compute.preflight` 显示版本、DLL 路径及测试结果；若 DLL 确实缺失，请修复对应 CUDA 安装并重启服务。`auto` 模式自检失败时使用 CPU，显式 `cuda` 模式会提前报错。 |
| 启动时报找不到 `solver` 模块 | 先切换到仓库根目录，再执行启动脚本 |
| 页面打不开或端口被占用 | 查看 `.runtime/server-error.log`，检查 `/api/health`，或用 `-Port 8766` 启动 |
| Codex 找不到 CLI 或无法连接 | 检查 CLI 安装、登录态和代理；API 使用者需明确设置 provider 与密钥 |
| Codex 等待超时 | 先核对连接及代理，再按需要调整 `THERMAL_CODEX_TIMEOUT_S`；延长等待本身不会修复连接失败 |
| “请先添加至少一个热源” | 检查草案是否真的创建了热源，以及面热源的选面数或点热源位置；可使用上面的完整示例 |
| 找不到“中心热源”、没有可保持的作用半径 | 当前没有这个热源时明确要求新建，并补充功率、位置与半径；已有热源则核对名称或序号 |
| 中心位置 `center_in_solid=false` | 继续回复有效的实体内位置，或明确同意保留坐标并改为外置；表面加热需另行确认表面坐标 |
| “表面中间”或“地面”无法定位 | 指定具体表面、刷选范围或核对后的 XYZ 坐标；不要将模型内部中心直接作为表面位置 |
| “确认并仿真”一直不可用 | 查看最后一轮待解决问题并继续回复；已有草案但输入了新补充时，也要先点击“发送补充”重新校验 |
| 更新后仍只看到“生成配置”且没有对话区 | 刷新页面加载新脚本，重新发一次初始需求；新页面第一轮完成后会出现“继续补充或回答问题” |
| 模型尺寸、质量或温升异常 | 核对 STL 单位、STEP 文件单位和额外倍率，并检查材料物性、区域体积与热源选区 |

依赖版本见 [requirements.txt](requirements.txt)，第三方组件声明见 [THIRD_PARTY.md](THIRD_PARTY.md)。
